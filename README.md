# Carbon Footprint Reflection for AI Image Generation Prototype

An interactive postgraduate dissertation prototype that helps creative practitioners reflect on the estimated carbon footprint of AI image-generation workflows. The application is a static React + Vite site: all state, dataset lookups, and carbon calculations run locally in the browser.

## Technical Stack

- React 19
- TypeScript
- Vite 6
- Tailwind CSS 4 via `@tailwindcss/vite`
- Lucide React icons
- Vitest for calculation utility tests

Recommended runtime: Node.js 24.x for local work and Vercel deployment. Minimum supported runtime is Node.js `>=20.19.0`, matching the installed Vite/plugin engine requirements.

## Dataset and Calculation Method

The dataset is stored locally in `src/data/modelsData.ts` and contains exactly 17 approved measured model records. Values are grams of CO2-equivalent per generated image for 512 x 512 and 1024 x 1024 outputs.

Model-based estimates are used only when the participant selects a known model included in the local dataset. The selected model's own resolution-specific value is multiplied by the image count for each workflow stage.

Representative estimates are used when the participant only knows the commercial tool, does not know the model, or selects an unlisted model. Commercial tools such as ChatGPT, Gemini, and Midjourney are contextual selections only; they are not automatically mapped to measured models. The representative method uses the resolution-specific dataset median:

- 512 x 512 median: `0.095194 gCO2` per image
- 1024 x 1024 median: `0.163645 gCO2` per image

Ideation, Iteration, and Refinement can each use independent counts and resolutions. Stage carbon values use each stage's own count and resolution. `totalImageCount` is the sum of the three stage counts, and `totalCarbon` is the sum of the three raw stage carbon values.

## Rounding Rules

Internal calculations keep raw floating-point values. Display formatting rounds only at the final presentation layer to three decimal places and sanitizes negative zero as `0.000 gCO2`. Display-rounded values are never reused as calculation inputs.

## Data Handling

This prototype does not submit or remotely store participant responses. All workflow inputs, reflection choices, and takeaways remain in local browser state and are reset when the participant selects "Start again" or reloads the page.

## Known Limitations

- The prototype is a front-end research artifact, not a carbon accounting product.
- The dataset and medians are fixed to the approved dissertation prototype values.
- Regeneration, iteration, and refinement counts are treated as generated-image counts for reflective estimation.
- No participant response export is provided because interview, questionnaire, audio, and observation data are collected separately by the researcher.

## Vercel Deployment

Use these settings when importing the GitHub repository into Vercel:

- Framework Preset: Vite
- Root Directory: project root containing `package.json`
- Install Command: `npm install`
- Build Command: `npm run build`
- Output Directory: `dist`
- Node.js Version: 24.x
- Environment Variables: none required
- Backend/Functions: none
- SPA routing: no `vercel.json` is required for the current state-based single-entry app

The project uses `package-lock.json` and npm. The previous AI Studio Bun lockfile was removed so Vercel does not infer Bun installation from `bun.lock`.

## GitHub to Vercel Workflow

1. Push the complete project root to GitHub.
2. In Vercel, create a new project from that repository.
3. Select the Vite framework preset.
4. Confirm the install command, build command, and output directory above.
5. Deploy.

## Redeployment

After future source changes, push to the connected GitHub branch. Vercel will create a new deployment automatically. If automatic deployments are disabled, open the Vercel project, choose the latest commit, and redeploy manually.

## Rollback

In the Vercel project dashboard, open Deployments, select a previous successful deployment, and choose Promote to Production. This restores the production URL to that earlier build without changing repository history.
